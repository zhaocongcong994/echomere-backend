# 命理工作流模型回归

回归入口覆盖倾听、看运、问事和随缘路由，以及事业、财富、关系和时间范围计划，产生可机读 JSON 报告。

## 安全默认模式

```bash
npm run eval
```

该命令固定使用 Mock Provider，即使 `.env.local` 中存在模型配置也不会请求外部 API。

## 真实模型模式

先在 `.env.local` 放入新生成的 `LLM_API_KEY`，再运行：

```bash
npm run llm:check
npm run eval -- --live
```

`llm:check` 通过 OpenAI-compatible `/models` 端点检查凭据、连接和配置的模型名，不会发起模型对话。`--live` 没有有效密钥时会直接失败，不会静默降级成 Mock。两个流程都不打印 API Key，回归报告也不保存完整用户或模型文本。

## 当前检查项

- 运行必须以 `run_completed` 结束。
- 实际模式必须与用例期望一致。
- 倾听/随缘倾听不调用命理工具。
- 看运必须读取档案；只有涉及年、月、时机或运势时才读取时间流。
- 问事必须完成一个卦象工具。
- 每个用例必须生成与主题、时间范围和工具数量一致的分析计划。
- 最终输出至少 20 个字符，包含 Prompt 版本，并通过分层回答质量检查。
- 报告每个用例的延迟、终止原因、质量重写次数、输入/输出 Token，并汇总所有草稿的总 Token 用量。

当前回归使用本地可重现工具数据，专门验证模型和 Agent 编排。Backend 真实工具链由双服务集成测试单独覆盖。
